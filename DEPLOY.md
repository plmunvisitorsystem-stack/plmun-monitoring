# Deploying for demo / alpha testing (free hosting)

This puts the system online at a free address such as **https://landayan-reporting.onrender.com**, for your panel, adviser, and alpha testers.

> ⚠️ **Demo and alpha testing only.** It uses the test accounts and sample data from `seed.sql` (shared password `Password123!`). Do not let real residents register until everything in **README → 10. Before real use** is done.

| Part | Free service | Notes |
|---|---|---|
| Website + API + live chat | **Render** (Free web service, Singapore) | One service; HTTPS included. **Sleeps after 15 minutes without visitors**; the next visit takes about a minute to wake it (live chat reconnects by itself). |
| Database | **Aiven for MySQL** (Free plan) | MySQL 8, encrypted connection. Aiven may power off an unused free service; turn it back on in the Aiven console. |
| Photos | **Cloudinary** (Free plan) | Report and "after" photos are stored as **private** images; the server still checks who may see each photo. |

You need: a GitHub account, and free accounts at render.com, aiven.io, and cloudinary.com. No credit card is needed for these free plans (check each site's current terms).

Time: about 30–45 minutes.

---

## 1. Database (Aiven)

1. Sign up at **https://aiven.io** → **Create service** → **MySQL** → plan **Free** → pick the region closest to the Philippines that the free plan offers → **Create**. Wait until the status is **Running**.
2. On the service's **Overview** page, note: **Host**, **Port**, **User** (`avnadmin`), **Password**, and download the **CA certificate** (`ca.pem`). Save `ca.pem` in `landayan-reporting\server\`. (It is ignored by Git and is never uploaded.)
3. On your computer, create **`server\.env.production`** (ignored by Git) with:
   ```
   DB_HOST=<Aiven host>
   DB_PORT=<Aiven port>
   DB_USER=avnadmin
   DB_PASSWORD=<Aiven password>
   DB_NAME=landayan_ers
   DB_SSL=true
   DB_SSL_CA_FILE=ca.pem
   ```
4. Create the tables and the test data on Aiven (in `landayan-reporting\server`):
   ```
   node --env-file=.env.production scripts/init-db.js --seed
   ```
   You should see `Done: 12 tables, 48 reports.` The values in `.env.production` are used instead of your local `.env`, so your XAMPP database is not touched. If the Aiven database already has tables, the script stops; add `--force` only if you really want to erase it and start again.

## 2. Photos (Cloudinary)

1. Sign up at **https://cloudinary.com** (Free plan).
2. On the **Dashboard**, copy the **API environment variable**: `CLOUDINARY_URL=cloudinary://<key>:<secret>@<cloud name>`. Keep only the part after `CLOUDINARY_URL=` for step 4.

## 3. Put the code on GitHub

1. On **https://github.com** create a new **private** repository, e.g. `landayan-reporting` (no README, no .gitignore).
2. In `landayan-reporting\` (the project already has a Git repository and a `.gitignore` that keeps `.env`, `.env.production`, `ca.pem`, `node_modules`, `uploads/` and `client/dist/` out):
   ```
   git add .
   git commit -m "Smart Environmental Reporting System"
   git remote add origin https://github.com/<your-username>/landayan-reporting.git
   git push -u origin main
   ```

## 4. Website + API (Render)

1. Sign up at **https://render.com** with your GitHub account.
2. **New** → **Blueprint** → choose the `landayan-reporting` repository. Render reads **`render.yaml`** (one free Node web service in Singapore; it builds the website, then starts the API, which also serves the website).
3. Render asks for the secret values:

   | Key | Value |
   |---|---|
   | `CLIENT_ORIGIN` | `https://landayan-reporting.onrender.com` (the address Render shows for the service; if the name is taken it adds letters, use the real one) |
   | `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD` | from Aiven (step 1) |
   | `DB_SSL_CA` | open `ca.pem` in Notepad and paste **all** of it, including the `-----BEGIN CERTIFICATE-----` and `-----END CERTIFICATE-----` lines |
   | `CLOUDINARY_URL` | from Cloudinary (step 2) |

   `JWT_SECRET` is generated by Render automatically; the other values are already in `render.yaml`.
4. **Apply**. The first build takes 3–5 minutes. When the log shows `API server running` and `Database: connected`, open the address.
5. Check:
   - `https://<your-address>/api/health` → `{"status":"ok","database":"connected"}`
   - the landing page, then log in as `admin`, `team1`, and `maria` (password `Password123!`)
   - as `maria`, submit a report **with a photo**, then open it: the photo shows. In Render, **Manual Deploy → Restart service**, and open the report again: the photo is still there (it is in Cloudinary).
   - live chat: `admin` sets **Available**; `maria` → **Help** → **Talk to staff** (during the Chat Schedule hours).

Every `git push` to `main` deploys again automatically.

## 5. Optional

- **Keep it awake during a demo:** open the site a minute before you present, or add a free monitor (e.g. UptimeRobot) that opens `/api/health` every 10 minutes. One always-on free service fits Render's free monthly hours.
- **Your own domain later:** buy a domain (or get the barangay's `.gov.ph` from DICT), then in Render → **Settings → Custom Domains** add it and create the DNS record Render shows. HTTPS is added automatically. Update `CLIENT_ORIGIN`.
- **Reset the demo data:** `node --env-file=.env.production scripts/init-db.js --seed --force` (erases everything on Aiven, including photos' database records; the photos stay in Cloudinary until deleted there).

## Troubleshooting

| Problem | Fix |
|---|---|
| Render build fails at `npm ci` | Make sure `client/package-lock.json` and `server/package-lock.json` were pushed. |
| `Database: NOT connected` in the Render log | Check the `DB_*` values; the Aiven service must be **Running**; `DB_SSL_CA` must contain the whole certificate. |
| `Database setup failed: ... self-signed certificate` when running init-db | `DB_SSL_CA_FILE` must point to the Aiven `ca.pem`. |
| The first page takes about a minute | The free service was asleep; it wakes on the first visit. |
| Photos disappear after a restart | `CLOUDINARY_URL` is missing on Render, so photos were saved on the free disk. Add it and redeploy; earlier photos are lost. |
| Times are 8 hours off | Do not change `DB_TIME_ZONE` (default `+08:00`, Philippine time). |
